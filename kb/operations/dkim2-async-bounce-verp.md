# DKIM2、异步退信与VERP：ESP需要做好的准备

本文是 DKIM2 系列的第二篇，由 Word to the Wise 的 steve 执笔，深入探讨异步退信（asynchronous bounce）机制、DKIM2 对其的变革性影响，以及 VERP（Variable Envelope Return Path，可变信封返回路径）技术。建议先阅读前一篇：[《DKIM2：它对邮件的未来意味着什么？》](dkim2-main.html)。

## 异步退信的基本概念

当我们被告知一封邮件未被投递时，有两种可能的通知方式：

* **同步退信（同步拒收）**：在 SMTP 事务过程中，目标服务器立即返回 5xx 或 4xx 响应码。5xx 表示"拒绝接收"，4xx 表示"临时延迟，请稍后重试"。
* **异步退信**：目标服务器先接受邮件，之后再发送一封"退信邮件"给原始邮件的 Return-Path（又称信封发件人、弹回域名或 SPF 域名）。退信邮件通常包含原始邮件的一部分内容，以及一些可读但不太友好的解释文本。

## 背散射：异步退信的长期痛点

异步退信的一个大问题是：垃圾邮件发送者经常伪造 Return-Path 地址，将无关第三方的邮件地址填入其中。这导致异步退信被发送到那些从未发送过邮件的人。这种现象称为**背散射（backscatter）**，几十年来一直是邮件系统工程中的严重约束。

背散射对接收方来说看起来就像垃圾邮件，因此会导致发送背散射的邮箱服务提供商自己被封禁。同时，从工程角度看这也是失礼行为——发送大量背散射的服务商会被视为"不专业"。

数十年的最佳实践要求**将背散射降到最低水平**——尽可能避免发送异步退信。

### 避免异步退信的三种传统方式

1. **在 SMTP 连接期间完成所有垃圾过滤和决策**——这意味着不再接受之后又想退回的邮件。这要求非常紧迫的决策时间窗口，以及足够的过滤容量以应对流量峰值（例如当全球所有营销人员都在周一的早上8点或整点准时发送邮件时）。
2. **暂缓接收（4xx 延迟响应）**——如果当下没有足够判断依据，可以暂时延迟，等发件方稍后重试时再作决定。此时可能已收集到同一邮件流的更多数据。
3. **丢弃邮件**——不投递也不通知。对于某些类型的邮件（如恶意软件）这是正确的决定。但对重要邮件，这破坏了邮件系统的诚信承诺。

另外还有一种非常普遍的方式：**投递到垃圾箱**。技术上不算"丢弃"，但对发件人和收件人来说几乎没有区别。

在某些管辖区域内，监管要求还会规定：如果邮件无法投递，必须通知发件人——这使得问题更加复杂。

## DKIM2 如何解决背散射

DKIM2 通过**要求 Return-Path 与签名域名对齐并签名**，使邮箱服务提供商可以信任 Return-Path 确实是发送退信的正确目标。具体来说：

* DKIM2 要求信封收件人和信封发件人都被记录在签名中
* 退信邮件被安全地发送给实际修改并签名了邮件的上一跳处理者
* 隐私保护的转发系统可以重写并重新签名转发邮件的 Return-Path，使它们自己接收异步退信，再转发给原始发件人的 Return-Path

这意味着我们可以**重新开始使用异步退信**了。这消除了邮箱服务提供商和第三方邮件过滤器工程中的一些显著成本和约束。大型消费级邮箱服务提供商非常渴望推进这一方案。

## 异步退信处理：ESP 必须面对的容量挑战

对合法的大批量邮件发送方来说，DKIM2 意味着大量原本被 5xx 拒绝、4xx 延迟或被投递到垃圾箱的邮件，将变为成功投递，然后转为一封延迟的异步退信。

许多退信会在投递后的几分钟内到达（邮箱服务提供商在容量允许时逐步处理入站邮件）。有些可能到第二天才到达（邮箱服务提供商需要收集更多数据才能做出判断）。但无论如何，**退信量将远大于今天看到的量**。

对 ESP 客户的影响不大——主要是报告方式会变化，可能需要在观念上适应投递率和退信数据的新含义。但 ESP 自身必须规划异步退信处理容量。不确定增长多少？可以从当前被拒绝或延迟的邮件数量开始估算。

**如果现有的异步退信自动化系统能够处理这种量级**，或者可以轻松扩容，那就不需要做什么。但如果正在丢弃异步退信、手工处理、或者转发给客户来处理——那么，是时候和平台工程师坐下来谈谈了。

## VERP：可变信封返回路径

异步退信的另一个问题在于处理成本。为了识别一封异步退信对应的是哪封原始邮件，你需要：

1. 接受异步退信
2. 解析退信正文，提取原始邮件
3. 找到足够细节来识别收件人、营销活动和客户
4. 记录该邮件已退回

Return-Path 本身就是一个邮件地址，它会像其他任何地址一样被垃圾邮件发送者抓取并轰炸。因此你的异步退信自动化系统必须接受大量垃圾邮件，从中筛选出真正的退信。

**VERP（Variable Envelope Return Path，可变信封返回路径）**可以消除大部分这些开销。它将处理退信所需的信息直接编码在邮件的 Return-Path 中。这意味着在 SMTP 会话的 "RCPT TO:" 阶段，你就拥有了所需全部数据。可以**立即记录退信并丢弃异步退信**，无需任何处理或存储。同时也可以在 RCPT 时直接拒绝那些明显不属于异步退信的邮件。

VERP 的出色之处在于它使异步退信自动化工程变得**更简单、更可靠**。但需要注意：一些人将"VERP"和"异步退信处理"混为一谈——它们不是一回事。你可以按自己需要的方式设计退信处理流程，如果当前的不使用 VERP 的方案也能可靠工作，那就不需要改变。

## 管理层摘要（TL;DR）

DKIM2 的推广部署预计将在未来一两年内使**异步退信量增长数个数量级**。

* 请现在就为此做规划
* VERP 是一个你应该了解的术语，但处理异步退信并不必须使用 VERP
* **你需要在 2026 年底前建立健壮的异步退信自动化处理能力**。否则你将开始丢失退信，从而损害合规和投递绩效
